# FinSight - Lending & Business Analytics Platform

An end-to-end analytics project for a **simulated** digital personal-loan lender: reproducible synthetic data -> validated ETL -> PostgreSQL -> SQL analytics -> Python statistics and ML -> Streamlit app, with Power BI specifications.

> **All data is synthetic.** Generated by `src/generation`, seed 42. Results describe the simulation, not real lending, and must not be quoted as real-world statistics. See `docs/simulation_design.md` for the planted effects.

## What is verified vs not
| Item | Status |
|---|---|

## Quick start (no database needed)
```bash
python -m venv .venv
source .venv/bin/activate            # Windows PowerShell: .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python -m etl.run_pipeline --generate --no-db     # ~1 min: generates data, cleans it, writes data/processed + reports/data_quality_report.md
streamlit run app.py                              # opens http://localhost:8501
pytest -q
```
Run these in a normal terminal (VS Code: Terminal > New Terminal) from the repository root.

## Full run with PostgreSQL
1. Install PostgreSQL 14+ and create a database and user (psql, as an admin):
   ```sql
   CREATE ROLE finsight LOGIN PASSWORD 'choose-a-password';
   CREATE DATABASE finsight OWNER finsight;
   ```
2. Copy `.env.example` to `.env` and put your values there (`.env` is git-ignored; never commit credentials). Alternatively set `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD` in your shell.
3. Load: `python -m etl.run_pipeline --generate` - **this drops and recreates the `raw`, `analytics` and `etl` schemas** in that database; use a dedicated one.
4. Run the SQL library: `python -m database.run_queries` (add `--export` to save CSVs, `--id Q04` for one query).
5. Optional reporting views for Power BI: `psql -d finsight -f database/powerbi_views.sql`.

## Streamlit app
Tabs: Portfolio overview, Credit & risk, Collections, Models & statistics, Data quality, About. Sidebar: data source (bundled synthetic data, or **upload your own CSVs** - held in session memory only, never written to PostgreSQL or disk), disbursement-date, employment, city-tier and channel filters. KPI definitions match SQL and DAX (see `src/kpis.py`). Optional database credentials: environment variables or `.streamlit/secrets.toml` (see `.streamlit/secrets.toml.example`).

Free hosting option: push to GitHub and deploy on Streamlit Community Cloud with main file `app.py`; the demo data is git-ignored, so either commit a small sample or have the app run on uploads. Community Cloud has no database; add secrets under App settings if you host PostgreSQL elsewhere. Review security before using any non-synthetic data.

## Power BI
`python -m powerbi.export_for_powerbi` writes flat CSVs to `powerbi/data/`. Follow `powerbi/dashboard_specification.md` (model, pages, visuals, slicers) with the measures in `powerbi/dax_measures.md`. Acceptance test: your cards must match the table at the end of `dax_measures.md`.

## Known limitations
See `docs/limitations.md`. Highlights: synthetic data; the simulation has no write-offs (so portfolio delinquency looks very high); right-censoring; association not causation; Power BI not built; no authentication in the app.
